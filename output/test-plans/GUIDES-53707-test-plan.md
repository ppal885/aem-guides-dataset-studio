**Expected Behaviour**
- EB-01: A topicref with only `@navtitle` and no `@href` is semantically equivalent to a DITA `<topichead>` element -- the DITA spec corpus confirms that `<topichead>` "produces a heading only, no content page" and a no-href topicref behaves identically: visible in the TOC/navigation tree but generating no output page of its own (RAG: dita_spec, topichead and topicref comparison); the AEM Sites publishing engine must therefore treat such a topicref as a navigation-only node and must not serialize a null outputPath for it into the `guides-navigation` JCR property.
- EB-02: `PathUtils.appendUnixSlash` must guard against a null `_path` argument at line 69-72 and must not throw NullPointerException; the peer method `getNodeParentPath` at lines 55-58 already guards correctly with a null-to-empty-string pattern that appendUnixSlash must adopt.
- EB-03: `fixUuidForMapAndTopic` must defensively skip or handle any TOC item where `parentTocItem.getOutputPath()` returns null or empty before calling `PathUtils.appendPath`, so that stale null-outputPath entries written by prior generations cannot trigger NPE on subsequent runs.
- EB-04: Child topics of a navtitle-only grouping topicref must be published to the AEM site as normal content pages -- the DITA spec confirms that child `<topicref>` elements under a no-href parent each point to their own .dita file and must each produce their own output page; the null-guard fix for the parent must not suppress child-topic publishing (RAG: dita_spec, topicref element spec).
- EB-05: After the fix, consecutive AEM Sites generations for the same preset must be idempotent; no null-path residue from a prior run's `guides-navigation` property may cause any subsequent generation to fail.
- EB-06: The correct fix contract, grounded in `<topichead>` semantics, is that the navtitle-only topicref should either be omitted from `guides-navigation` serialization entirely or stored with an explicitly empty string as outputPath -- never null; this aligns with how DITA-spec-conforming processors treat heading-only containers (RAG: dita_spec, topichead vs topicgroup comparison).
