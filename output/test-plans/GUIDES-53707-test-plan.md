# Test Plan: GUIDES-53707

**Understanding From Jira**
- Issue understood: GUIDES-53707 is a Critical customer-reported defect (Avaya, version 2608) where Native AEM Sites output generation fails with `NullPointerException: Cannot invoke "String.lastIndexOf(int)" because "_path" is null` on every generation attempt after the first; the first generation succeeds and the output site is created, but every subsequent trigger of the same preset crashes immediately with NPE in `fixUuidForMapAndTopic`.
- Why it matters: Avaya's AEM Sites publishing pipeline is completely blocked; the only workaround is to delete the generated JCR site nodes before each generation run, which is operationally unacceptable for a production content-delivery pipeline; the customer is Avaya, a high-priority SLA account.
- Requested outcome: AEM Sites generation must succeed on first and all subsequent runs for maps containing topicrefs with `@navtitle` but no `@href` (navigation-only grouping containers); `fixUuidForMapAndTopic` must not crash on the stale `guides-navigation` JCR property written by the first generation; deleting JCR site nodes must no longer be required as a prerequisite for each run.
- Lifecycle understood as: `Pre-Development UAC` -- issue is in Backlog (Fix version: Backlog); no PR or implementation branch is available; plan is authored from the live Jira description, confirmed stack trace, and static inspection of the Starling clone.
- Evidence boundary: Live Jira GUIDES-53707 fetched via JiraClient (status: Open, priority: Critical, component: Publishing, affected version: 2608); stack trace confirmed from Jira description (PathUtils.appendUnixSlash line 73 NPE); Starling clone at `C:\starling` inspected read-only (SHA `fdfa72777a2d73b2cdba6d2bdd60ea5535bad75f`, provisional -- not synchronized in this session); attachment `npe-test (1).zip` listed on the issue but not downloadable (Jira OAuth unavailable in this non-interactive session); behaviour_matters: false -- pure deterministic code bug (null guard missing in PathUtils.appendUnixSlash and fixUuidForMapAndTopic call site); RAG skipped per Phase 3 decision tree; automation repos at `C:\UI TEST\guides-ui-tests` and `C:\api automation\dxml-it-tests` inspected.

**Expected Behaviour**
- EB-01: A topicref with only `@navtitle` and no `@href` is a valid DITA navigation-only grouping container; the AEM Sites publishing engine must handle it gracefully by either omitting it from `guides-navigation` serialization or recording it with an empty-string sentinel for outputPath rather than serializing null.
- EB-02: `PathUtils.appendUnixSlash` must guard against a null `_path` argument at line 69-72 and must not throw NullPointerException; the peer method `getNodeParentPath` at lines 55-58 already guards correctly with a null-to-empty-string pattern that appendUnixSlash must adopt.
- EB-03: `fixUuidForMapAndTopic` must defensively skip or handle any TOC item where `parentTocItem.getOutputPath()` returns null or empty before calling `PathUtils.appendPath`, so that stale null-outputPath entries written by prior generations cannot trigger NPE on subsequent runs.
- EB-04: Child topics of a navtitle-only grouping topicref must be published to the AEM site as normal content pages; the null-guard fix for the parent must not suppress child-topic publishing.
- EB-05: After the fix, consecutive AEM Sites generations for the same preset must be idempotent; no null-path residue from a prior run's `guides-navigation` property may cause any subsequent generation to fail.
