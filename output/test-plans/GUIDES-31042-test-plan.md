**Expected Behaviour**

- The OASIS DITA table model the ticket cites defines @frame (all, top, bottom, topbot, sides, none) on <table> for the outer frame, and @rowsep/@colsep (0/1) for internal separators, with values inheriting from table to tgroup to colspec/spanspec to row to entry and the narrower scope overriding the wider one.
- DITA-OT PDF honours these attributes (screenshot left: @frame="none" yields no frame and no borders); DITA-OT is therefore the correct-behaviour oracle for this ticket.
- Native PDF currently ignores them: the inspected Native PDF CSS applies cell borders on all four sides unconditionally (see Code Touched), so @frame="none"/@rowsep="0" still render borders (screenshot right).
- @colsep is in scope for direct coverage because the same unconditional cell-border CSS rule sets both the vertical (colsep) and horizontal (rowsep) edges; it is not a separate mechanism. <simpletable> border semantics, AEM Sites/HTML5/JSON outputs, and DITA-OT PDF implementation are out of scope for the fix and are regression-only.
