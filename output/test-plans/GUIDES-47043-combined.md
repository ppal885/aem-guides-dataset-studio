**Understanding From Jira**
- Issue understood: In the AEM Assets Admin UI (Author), the DITA-specific action buttons (View source, Edit topic(s), Preview map, Share UUID link) show up on the wrong assets - they appear on non-DITA files such as PNG images and PDFs, and are missing on genuine DITA files (`.dita`, `.ditamap`) where authors actually need them. The Share UUID link button also produces a broken link (a URL with an empty `uuid=` value) when the asset has no GUID.
- Why it matters: A Critical, customer-reported (SLA3, customer cm-p63456) defect that clutters the Assets Admin UI for non-Guides teams and hides the controls DITA authors need on their own files; confirmed reproducible in the customer's stage environment and by their TAM in production.
- Requested outcome: The DITA-specific buttons must show only on assets DITA authors can actually edit (`.dita`, `.ditamap`, etc.), stay hidden on non-DITA assets (images, PDFs, PPTX, etc.), and the Share UUID link button must only appear (or must be disabled) when the asset actually has a GUID - never producing an empty-UUID link. A related cosmetic font-fallback issue in preview is out of scope for this plan (no code evidence gathered for it).

**Acceptance Criteria**

- AC-02: The Edit topics action is visible only for a matching DITA asset in the asset-details view (the same `.xml`/`.dita`/`.ditamap` extension check as View source), and is hidden for non-DITA assets.
- AC-03: When the asset-details view's suffix path resolves to a folder or another non-asset resource rather than a specific selected asset (for example the folder-level view in Assets Admin UI), View source and Edit topics remain visible rather than hidden, so a DITA author does not lose access to these actions from the folder-selection context - per-asset gating still applies once a specific asset is opened.
- AC-04: Clicking Share UUID link for an asset that has no GUID shows a clear error message (rather than silently copying a URL with an empty `uuid=` value to the clipboard); the button itself remains visible and clickable for all asset types, since this fix does not add a render-condition gate on this button - only the click-time behaviour for the no-GUID case changes.
- AC-05: A non-DITA asset such as a PNG or PDF hides View source and Edit topics, consistent with AC-01/AC-02; this fix does not change Preview map or Share UUID link visibility for non-DITA assets - see Open Questions for the resulting partial-scope gap against the originally reported four-button symptom.
