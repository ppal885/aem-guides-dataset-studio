**Acceptance Criteria**
- AC-01: When a New AEM Sites preset has Retain Temporary Files enabled and generation completes on the on-premise/desktop publish path, the temporary-files directory is zipped and the zip's repository path is recorded on the output history record, the same way it already happens for the PDF preset.
- AC-02: When Retain Temporary Files is enabled and the preset's output filename is blank for a New AEM Sites preset (as it always is for this preset type), the generated temp-files zip still gets a valid, non-degenerate filename (falling back to the preset's output title, then to a fixed default name) instead of an unusable filename made only of the `.zip` extension.
- AC-03: On the Cloud Service publish path, when Retain Temporary Files is enabled for a New AEM Sites preset, the generated zip of the temp-files output is persisted to the repository and the output history record's temp-files-zip location property is set, mirroring how the PDF/other presets already persist this for Cloud Service.
- AC-04: The New AEM Sites preset editor UI exposes a Retain Temporary Files toggle/switch, the same control already available for other output preset types, so that the flag this fix reads can actually be set to true by an author - without this, AC-01 through AC-03 can never be exercised through the product UI.
- AC-05: The temp-files zip generated and made downloadable for a New AEM Sites preset contains the actual DITA-OT temporary output files used for `componentMapping.json` element mapping, not only log files from an unrelated output folder.
- AC-06: The Cloud Service UI surfaces a download link/button for the temp-files zip once it has been persisted and its location recorded, consistent with how the download option already appears for other presets that support this.
