**Understanding From Jira**
- Issue understood: When a `.sch` file has a single `<sch:pattern>` containing two or more `<sch:rule>` elements, AEM Guides Schematron validation fires only the first rule; every subsequent rule in the same pattern is silently skipped, regardless of whether its context expression matches nodes in the topic being validated.
- Why it matters: Authors who write or adopt multi-rule patterns -- a common Schematron authoring idiom -- receive incomplete validation feedback. The concrete example from Jira: a straight-quote check (`context="//p"`) and an English-locale typographic-quote check (`context="//p[ancestor::*[@xml:lang='en-US']]"`) placed in one `<sch:pattern>` means the locale-specific check is never evaluated, leaving prohibited typography undetected in en-US content.
- Requested outcome: All `<sch:rule>` elements inside a `<sch:pattern>` fire and report violations; the Schematron panel in the XML editor and the `/bin/dxml/schematron` API response both return messages from every matching rule, not only the first.
- Lifecycle understood as: `Pre-Development UAC` -- Jira status is Open, fix version is Undecided, no code branch or PR for GUIDES-14502 found in any product or automation clone.
